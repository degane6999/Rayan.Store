1. Introduction & Présentation du projet

1.1 Contexte et objectifs

Rayan.store est une application web e-commerce développée dans le cadre du Bachelor CDA (Concepteur Développeur d'Applications) — 3ème année. Le projet consiste à concevoir et réaliser une boutique en ligne complète spécialisée dans la vente de produits informatiques et d'appareils mobiles.

Objectif principal Fournir une plateforme e-commerce moderne, sécurisée et performante permettant aux utilisateurs de découvrir, sélectionner et commander des produits tech avec une expérience utilisateur optimale.

Le projet répond aux 6 jalons définis dans le cahier des charges technique :

  1. Jalon 1 — Conception & Architecture (UML, wireframes, DB)
  2. Jalon 2 — Développement Front-End (React, TypeScript, Tailwind)
  3. Jalon 3 — Développement Back-End (Supabase, PostgreSQL, RLS)
  4. Jalon 4 — Intégration & Tests (Jest, Playwright)
  5. Jalon 5 — Sécurité & Performance (OWASP, RGPD)
  6. Jalon 6 — Déploiement & Documentation (CI/CD, Vercel)

Modèle de données — table products

CREATE TABLE products (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  category_id  uuid REFERENCES categories(id),
  name         text NOT NULL,
  slug         text UNIQUE NOT NULL,
  description  text,
  price        numeric(10,2) NOT NULL,
  original_price numeric(10,2),
  images       text[],
  stock        integer DEFAULT 0,
  is_featured  boolean DEFAULT false,
  specifications jsonb,
  created_at   timestamptz DEFAULT now()
);

Modèle de données — table orders

CREATE TABLE orders (
  id               uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id          uuid REFERENCES auth.users(id) NOT NULL,
  status           text DEFAULT 'pending',
  total_amount     numeric(10,2) NOT NULL,
  shipping_address jsonb,
  payment_method   text DEFAULT 'card',
  created_at       timestamptz DEFAULT now(),
  updated_at       timestamptz DEFAULT now()
);

4.2 Row Level Security (RLS)

Principe de sécurité fondamental Toutes les tables ont RLS activé. Aucune donnée n'est accessible sans politique explicite. Les utilisateurs ne peuvent accéder qu'à leurs propres données.

Exemples de politiques appliquées :

-- Lecture profil : seulement le propriétaire
CREATE POLICY "Users can read own profile"
  ON profiles FOR SELECT TO authenticated
  USING (auth.uid() = id);

-- Commandes : un utilisateur voit seulement les siennes
CREATE POLICY "Users can view own orders"
  ON orders FOR SELECT TO authenticated
  USING (auth.uid() = user_id);

-- Produits : lecture publique
CREATE POLICY "Products are publicly readable"
  ON products FOR SELECT TO anon, authenticated
  USING (true);

5.3 Gestion de l'état

L'application utilise le Context API natif de React avec deux contextes principaux :

ContexteÉtat géréPersistance
AuthContextuser, profile, loadingSession JWT Supabase (cookie)
CartContextitems, totalItems, totalPricelocalStorage (invité) + Supabase (connecté)
Stratégie de fusion panier Lors de la connexion, le panier localStorage est mergé avec le panier Supabase : les items existants voient leur quantité additionnée, les nouveaux items sont insérés. Le localStorage est ensuite vidé.

6. Sécurité

6.1 Authentification & Sessions

  • JWT Supabase — Tokens signés RSA-256, expiration 1h, refresh automatique
  • Email/password — Hashage bcrypt côté Supabase (non exposé client)
  • Session persistante — Stockage localStorage du refresh token
  • Deadlock prevention — Callbacks onAuthStateChange wrappés en IIFE async

6.2 OWASP Top 10

Risque OWASPMesure appliquéeStatut
A01 Broken Access ControlRLS sur toutes les tables, auth.uid() validé côté DBProtégé
A02 Cryptographic FailuresHTTPS obligatoire, JWT RSA-256, bcrypt passwordsProtégé
A03 InjectionSupabase SDK paramétré (pas de SQL brut), validation TSProtégé
A05 Security MisconfigurationClé anon publique (lecture seule), service_role côté serveurProtégé
A07 Auth FailuresRate limiting Supabase, erreurs generiques renvoyéesProtégé
A09 Logging FailuresLogs Supabase Dashboard + erreurs React boundaryPartiel

6.3 RGPD

Conformité RGPD Les données personnelles (email, nom, adresse) sont stockées dans l'UE (Supabase EU region), accessibles uniquement à leur propriétaire via RLS, et peuvent être supprimées sur demande via auth.deleteUser().
  • Données minimales collectées (principe de minimisation)
  • Consentement explicite à l'inscription (case CGV)
  • Aucun cookie tracking tiers
  • Politique de confidentialité accessible en footer

7. Tests & Qualité

7.1 Stratégie de tests

La pyramide de tests adoptée pour Rayan.store :

  • Tests unitaires (Jest + React Testing Library) — Composants, hooks, utilitaires
  • Tests d'intégration (Jest) — Flux auth, panier, checkout
  • Tests E2E (Playwright) — Parcours utilisateur complets

7.2 Exemples de tests unitaires

// CartContext — test ajout d'article
describe('CartContext', () => {
  it('should add item to cart', async () => {
    const { result } = renderHook(() => useCart(), {
      wrapper: CartProvider,
    });
    act(() => {
      result.current.addToCart({
        product_id: 'p1',
        name: 'iPhone 15 Pro',
        price: 1199,
        quantity: 1,
      });
    });
    expect(result.current.items).toHaveLength(1);
    expect(result.current.totalItems).toBe(1);
  });
});

8.1 Pipeline CI/CD (GitHub Actions)

name: CI/CD Rayan.store
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npm run typecheck
      - run: npm run lint
      - run: npm test -- --coverage
      - run: npm run build

  deploy-preview:
    needs: build-and-test
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
